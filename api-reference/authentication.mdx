Every request you make to the VOLLEY OSA REST API must be authenticated. The API uses API key authentication: you include your secret key as a Bearer token in the `Authorization` header of each HTTP request. There are no sessions, cookies, or OAuth flows — authentication is stateless and header-based, making it straightforward to use from any HTTP client, scripting environment, or server-side application.

## Authentication Scheme

Your API key is a secret credential tied to your VOLLEY OSA account and a specific set of permissions. You pass it in the `Authorization` header using the `Bearer` scheme:

```http
Authorization: Bearer YOUR_API_KEY
```

Replace `YOUR_API_KEY` with the actual key value you received from the VOLLEY OSA dashboard. The header must be present on every request — the API does not maintain authenticated sessions between calls.

<Warning>
  Treat your API key like a password. Never hard-code it in client-side code, commit it to source control, or expose it in logs. Use environment variables or a secrets manager to inject the key at runtime. If you believe a key has been compromised, rotate it immediately from the VOLLEY OSA dashboard.
</Warning>

## Code Examples

The following examples show how to pass the `Authorization` header in common HTTP clients and languages. In each case, replace `YOUR_API_KEY` with your actual key.

### curl

```bash
curl -X GET https://api.volleyosa.dev/v1/payloads \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json"
```

### Python

```python
import httpx

api_key = "YOUR_API_KEY"  # Load from environment variable in production

headers = {
    "Authorization": f"Bearer {api_key}",
    "Content-Type": "application/json",
}

response = httpx.get("https://api.volleyosa.dev/v1/payloads", headers=headers)
response.raise_for_status()
print(response.json())
```

<Note>
  The example above uses the `httpx` library. If you prefer `requests`, replace `httpx.get` with `requests.get` — the interface is identical for this use case.
</Note>

### JavaScript

```javascript
const apiKey = process.env.VOLLEY_API_KEY; // Never hard-code keys in source

const response = await fetch("https://api.volleyosa.dev/v1/payloads", {
  method: "GET",
  headers: {
    Authorization: `Bearer ${apiKey}`,
    "Content-Type": "application/json",
  },
});

if (!response.ok) {
  const error = await response.json();
  throw new Error(`API error ${error.code}: ${error.message}`);
}

const data = await response.json();
console.log(data);
```

## Authentication Error Responses

When authentication fails, the API returns one of two error responses:

### 401 Unauthorized

Returned when the `Authorization` header is missing entirely, the Bearer token is malformed, or the API key does not exist.

```json
{
  "error": "unauthorized",
  "message": "Missing or invalid API key. Provide a valid Bearer token in the Authorization header.",
  "code": 401
}
```

### 403 Forbidden

Returned when the API key is valid and authenticated, but it does not have permission to perform the requested operation. For example, a read-only key attempting to register or delete a payload.

```json
{
  "error": "forbidden",
  "message": "Your API key does not have permission to perform this operation.",
  "code": 403
}
```

<Note>
  If you receive a `403` error on an operation you expect to be permitted, check the permissions assigned to your API key in the VOLLEY OSA dashboard. Each key can be scoped to specific resources and actions.
</Note>
